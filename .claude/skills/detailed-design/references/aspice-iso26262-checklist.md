# A-SPICE SWE.3 / ISO 26262-6 상세설계·구현 자체 점검 체크리스트

본 스킬은 실무 보조 도구이며, **Automotive SPICE PAM 원문과 ISO 26262 Part 6 원문을 대체하지 않는다.** 공식 심사·인증·계약상 근거가 필요한 경우 원문과 대조해야 한다는 점을 산출물에 명시한다.

## A-SPICE 4.1 SWE.3 (Software Detailed Design and Unit Construction) Base Practice 자체 점검

| BP | 점검 항목 | 확인 위치(템플릿 섹션) |
|---|---|---|
| BP1 | 소프트웨어 단위를 상세설계로 개발했는가(모듈/함수/자료구조 수준) | 2. 모듈 분해, 5. 핵심 함수 계약, 6. 핵심 알고리즘 |
| BP2 | 상세설계 요소 간 인터페이스(함수 계약)를 정의했는가 | 5. 핵심 함수 계약, 3. 상세 호출관계 |
| BP3 | 소프트웨어 단위를 아키텍처와 일관되게 평가했는가 | 12. 단위와 요구사항 할당, 14. 추적성 |
| BP4 | 소프트웨어 단위를 개발(구현)했는가 | 11. 코딩 및 검증 규칙, 13. 구현 경계 |
| BP5 | 소프트웨어 단위와 상세설계 간 양방향 추적성을 확립했는가 | 14. 추적성 |
| BP6 | 소프트웨어 상세설계와 요구사항 간 일관성을 확립했는가 | 12. 단위와 요구사항 할당 |

각 BP에 대해 "충족/부분충족/미충족"과 근거(문서 섹션·문구)를 명시한다. 근거 없는 판정은 금지한다.

## ISO 26262-6 (소프트웨어 개발) 상세설계 및 구현 관련 자체 점검

| 항목 | 점검 질문 |
|---|---|
| 설계 원칙 반영 | 단위 수준 응집도/결합도, SOLID 판정 결과가 문서(2, 5장)에 명시적으로 기록되었는가 |
| 함수 계약 정의 | 모든 공개 함수에 사전/사후조건, 오류 계약, 시간 제약이 정의되었는가(5장) |
| 복잡도 제한 | 함수 크기·순환복잡도 상한 기준과 준수 여부가 기록되었는가(11장) |
| 방어적 프로그래밍 | 유효하지 않은 입력/예외/자원 실패에 대한 검출·처리·복구가 정의되었는가(10장) |
| ASIL별 구현 기법 제약 | 안전요구사항에서 파생된 ASIL 등급에 따라 포인터/동적메모리/재귀/인터럽트 사용 제한이 적용·문서화되었는가 |
| 코딩 표준/정적분석 | 실제 채택한 코딩 표준과 정적분석 도구 적용 여부가 명시되었는가(가정 금지, 실제 확인 필요) |
| 요구사항/아키텍처 추적 | 모든 SW 요구사항과 아키텍처 인터페이스가 구현 단위에 빠짐없이 할당되었는가(12, 14장) |

미충족 항목은 "미충족"으로 명시하고, 재설계 또는 보완 조치를 권고사항으로 제시한다. 존재를 가정하거나 임의로 충족 처리하지 않는다.

## 보고 원칙

- 실제 산출물(파일/섹션)을 열어 확인한 근거만 인용한다. 파일명·존재 여부만으로 판단하지 않는다.
- 산출물이 없거나 확인 불가능하면 "부재/미확인"으로 명시한다.
- 자체 점검 결과는 사용자가 사용한 언어(기본: 한국어)로 작성한다.
