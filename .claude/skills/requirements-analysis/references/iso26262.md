# ISO 26262 요구사항 관점 참고자료

> 아래는 ISO 26262(도로차량 기능안전) 요구사항 엔지니어링과 관련된 개념을 감사/작성 보조 목적으로 요약한 것이다. 공식 표준 원문(Part 4/5/6/8 등)을 대체하지 않으며, 실제 인증·심사 근거로는 반드시 원문을 확인해야 한다.

## 계층 구조 (V-model 정합)

```
Safety Goal (SG)
  └─ Functional Safety Requirement (FSR) — Part 4 (System)
       └─ Technical Safety Requirement (TSR) — Part 4/5/6
            └─ Software/Hardware Safety Requirement — Part 5/6
```

안전 관련 요구사항은 이 체인 어딘가에 위치해야 하며, 상위(Safety Goal)까지의 연결이 끊긴 안전요구사항은 불완전한 것으로 간주한다.

## 요구사항 특성 체크리스트 (ISO 26262-8 "요구사항 관리" 취지 요약)

작성한 모든 요구사항(특히 안전 관련)에 대해 아래를 점검한다.

| 특성 | 점검 질문 |
|---|---|
| 명확함(Unambiguous) | 하나의 해석만 가능한가 |
| 이해가능(Comprehensible) | 대상 독자(엔지니어, 심사원)가 배경지식 없이도 이해 가능한가 |
| 원자적(Atomic) | 하나의 요구사항이 하나의 요구만 담고 있는가 (and/or로 여러 요구를 묶지 않았는가) |
| 내적 일관성(Internally consistent) | 문장 내부에 모순이 없는가 |
| 실현가능(Feasible) | 현재 기술/자원으로 구현 가능한가 |
| 검증가능(Verifiable) | 통과/실패를 판정할 방법이 존재하는가 |
| 추상수준 적절(Abstract at its level) | System 레벨 요구사항에 구현 세부사항(특정 알고리즘 등)이 섞여 있지 않은가 |
| 추적가능(Traceable) | 상위(Safety Goal/FSR)와 하위(TSR/구현/테스트)로 양방향 추적되는가 |

## ASIL 관련 기록 항목

- 안전목표에서 파생된 요구사항에는 ASIL(QM, A, B, C, D) 등급을 명시한다.
- ASIL 분해(decomposition)를 적용한 경우, 분해 근거와 결과 ASIL을 함께 기록한다.
- 안전 관련 요구사항은 독립적 검토(review)를 거쳤는지 검토 상태 필드에 반영한다.

## A-SPICE와의 연결

- ISO 26262 요구사항 체인은 A-SPICE SYS.2(시스템 요구사항 분석)·SWE.1(SW 요구사항 분석)의 산출물과 동일한 문서/레코드에 공존하는 경우가 많다. 안전 속성(ASIL, Safety Goal 링크)은 A-SPICE 추적성 요구사항의 하위집합으로 취급하고 별도 표로 관리하지 않는다 — 하나의 요구사항 레코드 안에 두 관점의 필드를 함께 둔다 (`references/template.md` 참고).
