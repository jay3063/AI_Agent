## TPL-SWE1-001 문서 통제 및 목차

문서 통제(작성 문서 ID/명칭, 버전 및 베이스라인, 작성자/검토자), 변경 이력, 작성·검토·승인 상태 표를 문서 서두에 포함한다.

1. **목적 및 적용범위** — 1.1 목적 / 1.2 적용범위 / 1.3 적용 경계
2. **요구사항 작성 및 판정 규칙** — 2.1 식별 및 상태 규칙(ID/버전/상태/우선순위/변경통제) / 2.2 품질 판정 기준(명확성/원자성/일관성/검증가능성/추적성)
3. **상태와 우선순위** — 상태값/우선순위 의미, 전이 조건, 승인 책임
4. **기능 및 안전 관련 SW 요구사항** — 4.1 기능 요구사항 / 4.2 안전 관련 SW 요구사항(상위 안전요구 출처·할당 근거 유지)
5. **입력 데이터 사전** — 입력 신호명, 자료형, 단위, 범위, 유효성 조건, 오류 처리
6. **외부 인터페이스 요구** — 외부 시스템/HW/통신/사용자 인터페이스별 입력·출력·오류 계약
7. **비기능 및 환경 제약** — 성능/자원/신뢰성/사용환경/도구/플랫폼 제약(측정 가능한 기준)
8. **분석 결과와 가정** — 가정, 의존성, 상충 사항, 미결정 사항
9. **하향 할당 및 검증 계획** — 요구사항별 설계 할당 대상, 검증 수준/방법, 계획된 증거
10. **범위 밖 주장** — 이 문서/증거만으로 주장할 수 없는 시험수준·인증·적합성 범위
11. **추적성** — 상위 요구사항/Use Case/설계/코드/검증 산출물 간 양방향 연결 규칙과 위치
12. **참고자료** — 적용 표준, 고객 입력, 법규, 기술자료의 식별정보/버전/적용범위

## TPL-SWE1-002 Use Case 명세서 목차

문서 통제/변경이력/작성·검토·승인 상태는 SWE1-001과 동일 구조.

1. 목적 및 적용범위 (1.1~1.3)
2. **액터와 시스템 경계**
3. **Use Case 목록** — ID/명칭/목적/주 액터/관련 요구사항/우선순위
4. **Use Case 상세** (Use Case마다 복제)
   4.1 기본 정보(ID/명칭/목적/주 액터/이해관계자/관련 요구사항)
   4.2 사전조건과 트리거
   4.3 기본 흐름 (시간순 번호)
   4.4 대안 흐름
   4.5 예외 흐름 (오류/비정상 조건, 시스템 반응, 통지, 종료 상태)
   4.6 사후조건
5. **비대상 시나리오**
6. **추적성** — 상위 입력/SW 요구사항/설계/검증 항목 연결
7. **참고자료**

## TPL-TRC-001 양방향 추적 매트릭스 (열 구성)

| 열 | 설명 |
|---|---|
| Upper Req | 상위 요구사항 ID (Stakeholder/System/OEM 입력 등) |
| SW Req | SW 요구사항 ID (본 스킬이 도출하는 SWR-xxx) |
| Architecture | 할당된 아키텍처 요소/인터페이스 ID |
| Detailed Design | 할당된 상세설계 함수/모듈 ID |
| Code | 구현 파일/함수 위치 |
| SWE.4 | 단위시험 케이스/결과 ID |
| SWE.5 | 통합시험 케이스/결과 ID |
| SWE.6 | 시스템/자격시험 케이스/결과 ID |
| Coverage | 이 요구사항의 전체 커버리지 상태(TBD/Partial/Complete) |

이 스킬 단계(SWE.1)에서는 `Upper Req`, `SW Req` 열만 채울 수 있다. 나머지 열(Architecture~Coverage)은 이후 단계(architecture-design/detailed-design/tdd/integration-testing/sw-system-test)에서 채워지므로 **TBD로 명시하고 비워두지 않는다.**

## 이 스킬이 목차에 추가하는 산출물

- **사용자 확인 필요(User Confirmation Needed) 섹션** — 원문만으로 결정할 수 없는 우선순위/충돌/모호성을 최상단 또는 8절(분석 결과와 가정) 바로 뒤에 별도 섹션으로 둔다. 미결 항목이 있는 요구사항은 상태를 "Draft(부분)"로 표기하고 완결된 것처럼 서술하지 않는다.
- **용어집(glossary.md)** — 동일 개념에 다른 용어(예: "해제"의 unlock/RELEASE 혼용)를 쓰지 않도록 관리.
- **A-SPICE/ISO 26262 자체 점검 결과** — 문서 최종 섹션.
