# 명확성(Clarity) 체크리스트

모든 요구사항 문장은 아래 항목을 통과해야 한다. 하나라도 위반하면 재작성한다.

1. **단문·능동태**: 한 문장에 하나의 요구만 담는다. "그리고", "또는"으로 여러 요구를 묶지 않는다 (묶여 있으면 별도 ID로 분리).
2. **정형 문형 사용**: `<주체> shall <조건(있다면)> <행위> <성능/정확도 기준(있다면)>` 형태를 따른다.
3. **모호한 수식어 금지**: "적절히", "충분히", "가능한 한", "필요시", "usually", "대체로" 등 정량화되지 않은 표현을 쓰지 않는다. 반드시 수치/조건/기준으로 대체한다.
4. **미정의 대명사 금지**: "그것", "이것", "해당 시스템" 등이 무엇을 가리키는지 문맥 없이도 명확해야 한다.
5. **용어집 일치**: 용어집(`glossary.md`)에 정의된 용어만 사용하고, 동의어를 섞어 쓰지 않는다.
6. **수동태 지양**: "~되어야 한다" 대신 주체를 명시한 "~은/는 ~해야 한다" 형태를 우선한다. 주체가 불명확한 문장은 반려한다.
7. **검증 가능성**: 문장만 읽고 통과/실패를 판정할 방법이 떠오르지 않으면 명확성 미달로 간주한다.

## 위반 예시 → 수정 예시

| 위반 (모호함) | 수정 (명확함) |
|---|---|
| "시스템은 오류 발생 시 적절히 대응해야 한다" | "제어유닛은 센서 오류 감지 후 100ms 이내에 안전모드로 전환해야 한다" |
| "충분히 빠른 응답이 가능해야 한다" | "정상 부하 조건에서 요청의 95%는 200ms 이내에 응답해야 한다" |
| "사용자가 쉽게 이해할 수 있는 UI를 제공해야 한다" | "신규 사용자는 안내 없이 5분 이내에 핵심 과업을 완료할 수 있어야 한다 (사용성 테스트로 측정)" |
