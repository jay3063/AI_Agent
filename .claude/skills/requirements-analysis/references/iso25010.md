# ISO/IEC 25010 품질특성 기반 비기능 요구사항 작성 가이드

> ISO/IEC 25010의 제품 품질 모델(8대 특성)을 요구사항 태깅과 검증방안 설계에 사용한다. 하위 특성 명칭/정의의 정확한 원문은 표준 문서를 따르며, 아래는 실무 적용을 위한 요약이다.

## 8대 품질특성과 하위특성

| 특성 | 하위특성 (대표) | 전형적 측정 대상 |
|---|---|---|
| 기능 적합성 (Functional Suitability) | 완전성, 정확성, 적절성 | 기능 커버리지, 결과 정확도 |
| 성능 효율성 (Performance Efficiency) | 시간 반응성, 자원 사용성, 용량 | 응답시간, CPU/메모리 사용률, 처리량 |
| 호환성 (Compatibility) | 공존성, 상호운용성 | 타 시스템/버전과의 연동 성공률 |
| 사용성 (Usability) | 인식가능성, 학습성, 운용성, 오류방지, UI심미성, 접근성 | 과업완료율, 오류율, 표준화된 사용성 척도 점수(SUS 등) |
| 신뢰성 (Reliability) | 성숙성, 가용성, 결함허용성, 회복성 | MTBF, 가용률(%), 복구시간(MTTR) |
| 보안성 (Security) | 기밀성, 무결성, 부인방지, 책임추적성, 인증성 | 취약점 스캔 결과, 침투테스트 통과 여부, 인증 실패율 |
| 유지보수성 (Maintainability) | 모듈성, 재사용성, 분석용이성, 수정용이성, 시험용이성 | 정적분석 지표(결합도/응집도), 코드 커버리지 |
| 이식성 (Portability) | 적응성, 설치성, 대체용이성 | 대상 플랫폼별 빌드/설치 성공 여부 |

## 비기능 요구사항 작성 규칙

1. 반드시 하나 이상의 품질특성을 태깅한다.
2. 정량적 기준(수치+단위+조건)을 포함한다. 예: "정상 부하(초당 100 요청) 조건에서 95%의 요청은 200ms 이내에 응답해야 한다."
3. 검증방안은 아래 표처럼 "방법 + 도구/절차 + 합격기준"을 모두 포함해야 하며, 이 중 하나라도 없으면 실행 불가능한 검증방안으로 간주하고 반려한다.

## 검증방안 예시 (실행 가능 vs 불가능)

| 비기능 요구사항 (예) | 실행 가능한 검증방안 | 실행 불가능한 검증방안 (금지 예) |
|---|---|---|
| 응답시간 95%ile ≤ 200ms (초당 100 req 부하) | 부하테스트 도구(JMeter/k6 등)로 지정 부하 재현 후 95%ile 응답시간 측정, 기준 초과 시 실패 | "충분히 빠르게 응답해야 한다" (기준·측정방법 없음) |
| 가용률 99.9% 이상 (월간) | 운영 로그 기반 다운타임 집계, (전체시간-다운타임)/전체시간 계산 후 임계값 비교 | "가능한 한 안정적으로 동작해야 한다" |
| 신규 사용자가 안내 없이 5분 내 핵심 과업 완료 | 사용성 테스트(참가자 N명, 과업완료시간 측정), 평균 완료시간이 5분 초과 시 실패 | "사용자가 쉽게 쓸 수 있어야 한다" |
| 알려진 OWASP Top 10 취약점 0건 | 정적/동적 보안스캔 도구 실행 결과 기준, 발견 시 Critical/High 0건 조건 | "보안이 우수해야 한다" |

원칙: 검증방안 문장에 **측정 도구/절차**와 **정량적 합격 기준**이 둘 다 없으면 재작성 대상이다.
