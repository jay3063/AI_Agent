# 테스트 설계 기법 카탈로그 (공통 참조)

> 이 문서는 `tdd`, `integration-testing`, `sw-system-test` 세 스킬이 공통으로 참조하는 **단일 원천(single source of truth)**이다. 각 스킬은 이 카탈로그의 기법 명칭·정의를 그대로 사용하고 자체적으로 재정의/중복 기술하지 않는다. 레벨별로 강조되는 기법의 비중만 다르다.

## 기법 카탈로그 (어떻게 케이스를 만드는가)

| 기법 | 정의 |
|---|---|
| 요구사항분석 기반 테스트(Requirements-based Testing) | 요구사항/계약 문구(사전조건·사후조건·오류계약 등)에서 직접 케이스를 도출한다 |
| 동등분할(Equivalence Partitioning) | 입력 도메인을 유효/무효 클래스로 나누고 각 클래스의 대표값으로 검증한다 |
| 경계값분석(Boundary Value Analysis) | 유효 범위의 경계(최소/최대/경계값±1)를 검증한다 |
| 결정테이블 테스트(Decision Table Testing) | 여러 조건의 조합에 따른 기대 동작을 표로 도출해 검증한다 |
| 상태전이 테스트(State Transition Testing) | 상태 다이어그램의 전이/가드/금지 전이를 검증한다 |
| 조합 테스트(전 조건 조합, Combinatorial/Exhaustive Testing) | 관련 조건 수가 적어 전수 조합이 실행 가능할 때 모든 조합을 검증한다 |
| 페어와이즈 테스트(Pairwise Testing) | 조건·값의 조합 수가 많아 전수 조합이 비현실적일 때, 두 값씩의 조합을 최소 1회 커버하도록 축소한 조합을 검증한다(PICT 사용, 아래 참고) |
| 오류추정/경험기반 테스트(Error Guessing / Experience-based Testing) | 계약 위반 입력, 유사 시스템의 결함 이력, 탐색적 테스트 등 경험에 근거해 실패가 예상되는 조건을 검증한다 |
| 엣지 케이스 분석(Edge Case Analysis) | 동시성/타이밍 등 경계값분석·동등분할로 포착되지 않는 극단·특이 조건을 검증한다 |

이 표는 **"어떻게 케이스를 만드는가"(design technique)** 카탈로그다. **"무엇을 시험하는가"(test method)** — 예: 인터페이스 시험, 결함주입 시험, 자원사용 시험, 백투백 비교 시험 — 는 시험 레벨마다 성격이 달라 이 문서에서 다루지 않는다. 통합시험 레벨의 방법 목록은 `integration-testing` 스킬의 `references/iso26262-test-methods.md`를 따른다.

## 명명 규칙 (동의어 통일)

- "동치 클래스"와 "동등분할"은 같은 기법이며, 이 프로젝트에서는 **동등분할**로 통일해 기록한다.
- "경험 기반 테스트"와 "오류추정"은 같은 기법이며, 이 프로젝트에서는 **오류추정/경험기반 테스트**로 통일해 기록한다.
- 각 시험 케이스에는 이 표의 명칭을 그대로 기록한다. 임의로 새 이름을 짓지 않는다.

## 레벨별 적용 매트릭스

| 기법 | 단위(TDD, `tdd`) | 통합(SWE.5, `integration-testing`) | 시스템/자격(SWE.6, `sw-system-test`) |
|---|---|---|---|
| 요구사항분석 기반 | ✓ (함수 계약 기준) | ✓ (인터페이스 계약 기준) | ✓ (SW 요구사항 기준 — 기본 기법) |
| 동등분할 | ✓ | ✓ | ✓ |
| 경계값분석 | ✓ | ✓ | ✓ |
| 결정테이블 | ✓ (정책 함수) | 필요 시 | ✓ (정책성 요구사항) |
| 상태전이 | ✓ | 필요 시 | ✓ (상태 기반 요구사항) |
| 조합/페어와이즈 | – | 조건 조합이 있는 인터페이스에 필요 시 | ✓ (다중 입력조건 요구사항, PICT) |
| 오류추정/경험기반 | ✓ | ✓ | ✓ |
| 엣지 케이스 | – | 필요 시(동시성/타이밍) | ✓ |

## PICT를 이용한 조합/페어와이즈 테스트 생성

- 페어와이즈 조합 생성에는 오픈소스 도구 **PICT**를 사용한다.
- 전수 조합(모든 조건의 조합)이 필요하면 PICT의 `/o:max` 옵션을 사용한다.
- 입력 조건과 값 목록을 PICT 모델 파일(`.txt`)로 작성하고 `pict model.txt > cases.txt` 형태로 실행해 조합 목록을 생성한 뒤, 그 결과를 실제 시험 케이스의 Stimulus/입력값으로 변환한다.

## 사용 원칙

- 각 시험 케이스에는 실제로 적용한 기법 명칭을 위 카탈로그 표기(동의어 통일 규칙 포함) 그대로 기록한다.
- 의미 없이 커버리지 수치 달성만을 목적으로 기법을 적용하지 않는다 — 기법은 실제 위험/조건을 다루기 위해 선택한다.
