# 인터페이스 명세 규칙 및 통합 순서 정의

## 1. 인터페이스 정의 원칙 (필수)

- **컴포넌트 간 통신은 반드시 정의된 인터페이스로만 이루어진다.** 전역 변수 공유, 다른 컴포넌트 내부 필드/상태에 대한 직접 접근, 문서화되지 않은 사이드채널 통신을 금지한다.
- 각 컴포넌트는 **제공 인터페이스(Provided Interface)**와 **요구 인터페이스(Required Interface)**를 구분하여 명시한다(포트 개념). 요구 인터페이스는 구체 컴포넌트가 아닌 추상 인터페이스에 대한 의존으로 표현한다(DIP).
- 인터페이스는 계약(Design by Contract) 형태로 정의한다: 무엇을 언제 호출할 수 있고, 무엇을 보장하는지 명확히 한다.

### 인터페이스 명세 테이블 (템플릿 6장에 사용)

| 필드 | 설명 |
|---|---|
| 인터페이스 ID | 고유 식별자 (예: `IF-SWC-004`) |
| 구분 | 내부(6.1) / 외부(6.2) |
| 제공자(Provider) | 이 인터페이스를 구현/노출하는 컴포넌트 |
| 사용자(Consumer) | 이 인터페이스를 호출/구독하는 컴포넌트(복수 가능) |
| 연산/시그니처 | 함수명, 파라미터, 반환값 또는 이벤트/메시지 스키마 |
| 데이터 계약 | 데이터 타입, 단위, 유효범위, 정밀도 |
| 사전조건 / 사후조건 | 호출 전 성립해야 하는 조건 / 호출 후 보장되는 결과 |
| 시간 제약 | 호출 주기, 최대 응답시간, 타임아웃, 동기/비동기 여부 |
| 오류 계약 | 오류 코드/예외, 오류 시 상대 컴포넌트의 기대 동작 |
| 재진입성/스레드 안전성 | 동시 호출 가능 여부 |
| 버전 | 인터페이스 변경 이력 추적용 |
| 할당 요구사항 ID | 이 인터페이스가 만족해야 하는 SW 요구사항 |

- 외부 인터페이스(6.2)는 HW/통신/사용자/외부 서비스와의 경계이므로, 추가로 변환/프로토콜 책임 주체를 명시한다.

## 2. 정적 의존성 검증 (템플릿 5장과 연계)

1. 컴포넌트 의존 그래프를 Mermaid로 작성한다(방향 = "사용한다" 또는 "의존한다").
2. 순환 의존(cyclic dependency)이 있는지 확인한다. 발견되면 인터페이스를 추출하여 역전(DIP)하거나 공통 상위 추상화로 분리해 순환을 제거한다 — 순환을 "허용"으로 남기지 않는다.
3. 의존 방향이 안정된 추상화(인터페이스)를 향하는지, 구체 구현을 향하지 않는지 확인한다.

## 3. 통합 순서 정의 (필수, 템플릿 11장)

### 전략 선택

| 전략 | 설명 | 적합 상황 |
|---|---|---|
| 상향식(Bottom-up) | 하위/기반 컴포넌트부터 통합, 상위는 드라이버로 대체 | 하위 컴포넌트 리스크·재사용도가 높을 때 |
| 하향식(Top-down) | 상위/제어 컴포넌트부터 통합, 하위는 스텁으로 대체 | 상위 제어 흐름 검증이 우선일 때 |
| 위험 기반(Risk-based)/샌드위치 | 고위험·고ASIL 인터페이스를 우선 통합 | 안전 필수 기능이 명확히 식별될 때 |
| 빅뱅(Big-bang) | 전체를 한 번에 통합 | 원칙적으로 지양 — 소규모/저위험 한정, 근거 명시 필수 |

선택한 전략과 그 근거(왜 이 순서가 리스크를 최소화하는지)를 명시한다.

### 통합 순서 테이블

| 순서 | 통합 대상(컴포넌트/인터페이스) | 선행조건(먼저 통합되어야 하는 컴포넌트) | 필요 스텁/드라이버 | 검증 목적 | 순서 근거 |
|---|---|---|---|---|---|
| 1 | ... | 없음(최하위) | ... | ... | ... |
| 2 | ... | 1 | ... | ... | ... |

- 순서 근거 칸에는 "왜 이 컴포넌트가 이 시점에 통합되어야 하는가"(의존성, 위험도, ASIL, 재사용성 등)를 반드시 기술한다. 근거 없는 순서 배정은 반려한다.
- 이 표는 `TPL-SWE5-001_SW 통합전략 및 통합시험 명세서 템플릿`, `TPL-SWE5-002_SW 통합시험 케이스 템플릿`의 입력이 되므로, 통합 대상/순서 식별자를 그 문서에서도 그대로 재사용할 수 있도록 명명한다(추적성 유지).
