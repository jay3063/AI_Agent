# 설계 원칙: 응집도/결합도, SOLID, ISO 26262-6

## 1. 응집도(Cohesion) — 높을수록 좋음

컴포넌트 설계 시 아래 순서(위가 더 바람직함)로 응집도 유형을 판정하고 기록한다. **기능적 응집(Functional Cohesion)을 목표로 하며, 논리적/우연적 응집은 반려 후 재설계한다.**

| 순위 | 유형 | 설명 |
|---|---|---|
| 1 (최상) | 기능적(Functional) | 단일하고 잘 정의된 기능을 위해 모든 요소가 협력 |
| 2 | 순차적(Sequential) | 한 요소의 출력이 다음 요소의 입력이 되는 처리 순서로 묶임 |
| 3 | 통신적(Communicational) | 동일 데이터에 대해 다른 연산을 수행하는 요소들이 묶임 |
| 4 | 절차적(Procedural) | 특정 실행 순서를 따르기 위해서만 묶임 |
| 5 | 시간적(Temporal) | 같은 시점(예: 초기화)에 실행되어야 해서 묶임 |
| 6 | 논리적(Logical) | 유사한 종류라는 이유만으로 묶임(예: "모든 입력 처리") |
| 7 (최하) | 우연적(Coincidental) | 특별한 관계 없이 묶임 |

컴포넌트 책임(템플릿 섹션 4) 작성 시 각 컴포넌트에 응집도 유형과 판정 근거를 명시한다.

## 2. 결합도(Coupling) — 낮을수록 좋음

컴포넌트 간 관계(템플릿 섹션 3.2, 5) 작성 시 아래 순서(위가 더 바람직함)로 결합도 유형을 판정한다. **데이터 결합(Data Coupling)을 목표로 하며, 공통/내용 결합은 금지 사항으로 취급하고 재설계한다.**

| 순위 | 유형 | 설명 | 허용 여부 |
|---|---|---|---|
| 1 (최상) | 데이터(Data) | 필요한 데이터만 매개변수로 전달 | 권장 |
| 2 | 스탬프(Stamp) | 필요 이상의 데이터 구조 전체를 전달 | 제한적 허용(정당화 필요) |
| 3 | 제어(Control) | 상대 동작을 제어하는 플래그를 전달 | 지양, 불가피 시 근거 명시 |
| 4 | 공통(Common) | 전역/공유 데이터 영역을 함께 참조 | **금지** (예외 시 안전 분석 및 승인 필요) |
| 5 (최하) | 내용(Content) | 다른 컴포넌트의 내부 구조/상태를 직접 참조·변경 | **금지** |

**반드시** 모든 컴포넌트 간 상호작용은 6장(인터페이스 명세)에 정의된 인터페이스를 통해서만 이루어져야 하며, 내부 필드·전역 상태에 대한 직접 접근은 결합도 위반으로 반려한다.

## 3. SOLID 원칙 자체 점검 (컴포넌트별 필수)

| 원칙 | 점검 질문 | 위반 시 조치 |
|---|---|---|
| SRP (단일 책임) | 이 컴포넌트가 변경되어야 할 이유가 하나뿐인가? 책임 문장이 "~하고 ~한다"처럼 복수인가? | 책임을 분리하여 컴포넌트를 나눈다 |
| OCP (개방-폐쇄) | 신규 요구사항/변형이 추가될 때 기존 컴포넌트 수정 없이 확장(신규 구현체, 플러그인, 구독자 추가)으로 대응 가능한가? | 확장 지점(인터페이스/추상화)을 식별해 재설계 |
| LSP (리스코프 치환) | 동일 인터페이스의 구현체를 교체해도 호출자의 계약(사전/사후조건, 오류 계약)이 깨지지 않는가? | 인터페이스 계약을 명확히 하거나 하위 타입 분리 |
| ISP (인터페이스 분리) | 인터페이스가 모든 사용자에게 필요한 연산만 노출하는가, 아니면 일부만 쓰는 거대 인터페이스인가? | 사용자별로 인터페이스를 분리 |
| DIP (의존 역전) | 상위/정책 컴포넌트가 하위/구체 구현이 아닌 인터페이스(추상화)에 의존하는가? 의존 방향이 안정된 추상화 쪽으로 향하는가? | 인터페이스를 상위 계층에 정의하고 하위가 이를 구현하도록 반전 |

각 컴포넌트 항목마다 위 5개 질문에 대한 판정(Pass/Fail)과 근거를 기록한다. Fail 항목은 재설계 없이 통과시키지 않는다.

## 4. ISO 26262-6 아키텍처 설계 원칙과의 정합

ISO 26262 Part 6(소프트웨어 개발)에서 요구하는 소프트웨어 아키텍처 설계 원칙(계층 구조, 컴포넌트/인터페이스의 제한된 크기와 복잡도, 높은 응집도, 낮은 결합도, 명확히 정의된 인터페이스, 오류 검출/처리 메커니즘, 필요 시 ASIL 등급에 따른 설계 기법 — 예: 포인터/재귀/동적 객체/인터럽트 사용 제한 등)을 아키텍처 설계 원칙(템플릿 섹션 2)에서 항목별로 어떻게 반영했는지 명시한다.

- 계층 구조(Hierarchical structure): 섹션 3의 계층/요소 분해가 상하위 관계를 명확히 표현하는가.
- 컴포넌트/인터페이스 크기 제한: 과도하게 큰 컴포넌트나 인터페이스가 없는가(임계값을 프로젝트 기준으로 정의).
- 높은 응집도/낮은 결합도: 본 문서 1절/2절 판정표로 근거 제시.
- 명확히 정의된 인터페이스: 6장의 인터페이스 명세가 모든 상호작용을 커버하는가.
- 오류 검출 및 처리(오류 격리): 9장(오류 격리와 안전 동작)과의 연계.
- ASIL 등급별 설계 기법 제약(해당하는 경우): 안전요구사항에서 파생된 ASIL 등급에 따라 포인터/동적 메모리/재귀/인터럽트 사용 제한 여부를 명시.

**주의**: 본 참고자료는 실무 적용을 돕기 위한 요약이며, ASIL 등급별 정확한 권고 표는 반드시 ISO 26262-6 원문(해당 표)과 대조해 확정한다. 이 스킬의 산출물은 원문을 대체하지 않는다.
