## 목차 및 섹션별 작성 안내

1. **목적 및 적용범위**
   1.1 목적 — 문서가 지원하는 개발/검증 활동과 기대 결과
   1.2 적용범위 — 대상 제품, SW 구성요소, 생명주기 단계, 대상 조직
   1.3 적용 경계 — 포함/제외 범위, 외부 조직·상위 산출물과의 경계
2. **아키텍처 설계 원칙** — 분해, 결합도, 응집도, 인터페이스, 오류 격리, 변경 용이성에 적용한 원칙 (`references/design-principles.md` 근거로 작성)
3. **논리 아키텍처**
   3.1 아키텍처 요소 — 요소 ID, 명칭, 목적, 제공 기능, 소유 책임
   3.2 관계와 제약 — 허용된 의존 방향, 호출 관계, 공유 자원, 금지된 결합
4. **컴포넌트 책임** — 컴포넌트별 책임, 입력, 출력, 상태, 오류 처리, 할당 요구사항
5. **정적 의존성** — 패키지/모듈/컴포넌트 정적 의존성, 순환 의존 방지 기준
6. **인터페이스 명세** (`references/interface-and-integration.md` 형식 사용)
   6.1 내부 인터페이스 — SW 요소 간 API, 이벤트, 데이터 저장소, 동기화 규칙
   6.2 외부 인터페이스 — HW/통신/사용자/외부 서비스 경계와 변환 책임
7. **동적 동작** — 주요 시나리오 호출 순서, 데이터 흐름, 조건별 분기(시퀀스/활동)
8. **상태 전이** — 상태, 진입/종료 조건, 전이 이벤트, 가드, 금지 전이
9. **오류 격리와 안전 동작** — 오류 감지 위치, 전파 차단, 안전 상태, 복구, 진단 정보 책임
10. **품질속성 분석** — 성능/신뢰성/유지보수성 등 시나리오 기반 설계 대응 분석
11. **통합 전략** (`references/interface-and-integration.md`의 통합 순서 형식 사용) — 통합 단위, 순서, 인터페이스 검증, 스텁/드라이버, 회귀 범위
12. **요구사항 할당** — SW 요구사항을 아키텍처 요소/인터페이스에 할당, 누락·중복 확인
13. **자원 및 배포 경계** — 실행 노드, 프로세스, 메모리, CPU, 저장소, 배포 제약
14. **추적성** — 요구사항 ↔ 아키텍처 요소 ↔ 상세설계 ↔ 통합 검증 간 연결
15. **참고자료** — 입력 요구사항, 적용 표준, 모델 원본, 설계 결정 기록(ADR)

## 이 스킬이 목차에 추가하는 산출물 (템플릿 섹션 2, 15와 연계)

- **아키텍처 후보 제안 및 선정 기록(ADR)** — 섹션 2 앞 또는 섹션 15 부속서로 포함. 후보 목록, 비교표, 선정 근거, 선택한 이해관계자를 기록한다.
- **SOLID / 응집도·결합도 자체 점검표** — 섹션 4(컴포넌트 책임) 뒤에 첨부.
- **A-SPICE SWE.2 / ISO 26262-6 자체 점검 결과** — 문서 최종 섹션(참고자료 앞 또는 뒤)에 별도 섹션으로 추가.
