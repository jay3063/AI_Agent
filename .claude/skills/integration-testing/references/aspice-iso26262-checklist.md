# A-SPICE SWE.5 / ISO 26262-6 통합시험 자체 점검 체크리스트

본 스킬은 실무 보조 도구이며, **Automotive SPICE PAM 원문과 ISO 26262 Part 6 원문을 대체하지 않는다.** 공식 심사·인증·계약상 근거가 필요한 경우 원문과 대조해야 한다는 점을 산출물에 명시한다.

## A-SPICE 4.1 SWE.5 (Software Integration Test) Base Practice 자체 점검

| BP | 점검 항목 | 확인 위치(템플릿 섹션) |
|---|---|---|
| BP1 | 소프트웨어 통합시험 전략을 개발했는가(통합 단위/순서/환경) | 2. 통합 원칙, 3. 통합 항목과 순서 |
| BP2 | 통합시험 케이스를 개발했는가(인터페이스/요구사항 기반) | 6. 통합시험 케이스 요약, TPL-SWE5-002 |
| BP3 | 통합시험 환경이 정의된 대로 확보되었는가 | 4. 환경 및 형상 |
| BP4 | 소프트웨어 요소 간 통합 및 인터페이스 시험을 아키텍처 통합 순서에 따라 수행했는가 | 3. 통합 항목과 순서, 7. 시험 설계기법 |
| BP5 | 통합시험 결과를 요구사항/인터페이스와 대조해 평가했는가 | TPL-SWE5-003, 11. 추적성과 보고 |
| BP6 | 회귀 시험을 수행했는가(변경 영향 범위) | 9. 회귀 전략 |
| BP7 | 양방향 추적성(인터페이스 ↔ 시험 케이스 ↔ 결과 ↔ 결함)을 확립했는가 | 11. 추적성과 보고, 13. 추적성 |
| BP8 | 결과를 이해관계자와 합의(리뷰/승인)했는가 | 문서 통제(작성/검토/승인 상태) |

각 BP에 대해 "충족/부분충족/미충족"과 근거(문서 섹션·문구)를 명시한다. 근거 없는 판정은 금지한다.

## ISO 26262-6 통합시험 관련 자체 점검

| 항목 | 점검 질문 |
|---|---|
| 시험 기법 선정 | 인터페이스 시험/요구사항기반 시험이 모든 인터페이스에 적용되었는가. ASIL에 따라 결함주입/자원사용 시험이 적절히 반영되었는가(`references/iso26262-test-methods.md`) |
| 케이스 도출 기법 | 각 시험 케이스가 요구사항분석/동등분할/경계값분석/오류추정 중 어떤 기법으로 도출되었는지 명시되었는가 |
| 테스트 베이시스 | 시험 케이스가 아키텍처 인터페이스 명세와 통합 순서를 근거로 도출되었는가(임의 케이스가 없는가) |
| 통합 순서 준수 | 실제 시험 실행이 아키텍처 통합 순서를 따랐는가, 선행 항목 통과 전 후행 항목을 시험하지 않았는가 |
| 구조적 커버리지 | 함수 커버리지와 Call 커버리지가 각각 100%로 실측되었는가(`references/coverage-and-tools.md`). 미달 시 갭과 보완 케이스가 기록되었는가 |
| 오류 격리 검증 | 아키텍처 9장(오류 격리와 안전 동작)에서 정의한 오류 검출/전파 차단이 결함주입 시험으로 검증되었는가 |
| 자원 사용 검증 | 아키텍처 13장(자원 및 배포 경계) 예산이 자원사용 시험으로 검증되었는가 |

미충족 항목은 "미충족"으로 명시하고, 보완 시험 케이스 또는 재설계 권고와 함께 제시한다. 존재를 가정하거나 임의로 충족 처리하지 않는다.

## 보고 원칙

- 실제 산출물(파일/섹션/도구 실행 결과)을 열어 확인한 근거만 인용한다. 파일명·존재 여부만으로 판단하지 않는다.
- 산출물이 없거나 확인 불가능하면 "부재/미확인"으로 명시한다.
- 자체 점검 결과는 사용자가 사용한 언어(기본: 한국어)로 작성한다.
