# ISO 26262-6 소프트웨어 통합시험 기법

**주의**: 아래 표는 ISO 26262-6(소프트웨어 개발)의 소프트웨어 통합시험 관련 표(시험 기법 표, 시험케이스 도출 기법 표)를 실무 적용을 돕기 위해 요약한 것이다. ASIL별 권고 수준(권장/강력 권장 여부)은 반드시 실제 프로젝트가 보유한 ISO 26262-6 원문과 대조하여 확정한다 — 이 표는 원문을 대체하지 않는다.

## 1. 통합시험 기법 (시험을 어떻게 수행하는가)

| 기법 | 설명 | 비고 |
|---|---|---|
| 요구사항기반 시험(Requirements-based test) | 할당된 SW 요구사항/인터페이스 요구사항을 기준으로 시험 케이스를 도출 | 모든 ASIL에서 기본으로 수행 |
| 인터페이스 시험(Interface test) | 아키텍처 설계서의 인터페이스 명세(제공/요구 포트, 데이터 계약, 사전/사후조건, 오류 계약)를 기준으로 각 인터페이스의 정상/경계/오류 동작을 검증 | 이 스킬의 **테스트 베이시스** 핵심 기법 — 모든 ASIL에서 기본으로 수행 |
| 결함주입 시험(Fault injection test) | 통신 오류, 잘못된 입력, 자원 고갈 등 결함을 인위적으로 주입해 오류 검출/전파 차단(아키텍처 9장 오류 격리와 안전 동작)이 설계대로 동작하는지 검증 | ASIL이 높아질수록 권고 수준 상승 — 대상 ASIL 확인 |
| 자원사용 시험(Resource usage test) | 메모리/CPU/스택/타이밍 등 자원 사용이 아키텍처 13장(자원 및 배포 경계) 예산 내에 있는지 검증 | ASIL이 높아질수록 권고 수준 상승 |
| 백투백 비교 시험(Back-to-back comparison test) | 모델(있는 경우)과 코드의 동작을 동일 입력에 대해 비교 | 모델 기반 개발을 사용하는 경우에 한함 |

## 2. 시험 케이스 도출 기법 (케이스를 어떻게 만드는가)

케이스 도출 기법(동등분할/경계값분석/오류추정/결정테이블/상태전이 등)의 명칭·정의는 이 문서에서 재정의하지 않는다. **`test-design-techniques` 스킬(공통 카탈로그)을 그대로 사용한다** — `tdd`, `sw-system-test` 스킬도 동일한 카탈로그를 참조하므로, 요구사항 분석 → 아키텍처 → 상세설계 → 구현 → 통합시험 → 시스템/자격시험 전 단계에서 기법 명칭이 일관된다. 통합시험 레벨에서 주로 쓰는 기법은 요구사항분석 기반, 동등분할, 경계값분석, 오류추정/경험기반이며(카탈로그의 "레벨별 적용 매트릭스" 참고), 조건 조합이 있는 인터페이스에는 결정테이블/조합·페어와이즈도 적용한다.

통합시험 케이스에는 위 1절(무엇으로 시험하는가, ISO 26262-6 방법)과 2절(어떻게 케이스를 만드는가, `test-design-techniques` 기법)을 함께 기록한다: 예) "인터페이스 시험 / 경계값분석".

## 3. ASIL별 적용 우선순위 판단

1. 대상 인터페이스/통합 항목이 파생된 안전요구사항의 ASIL 등급을 확인한다(없으면 QM으로 간주하되, 근거를 명시한다).
2. ASIL이 높을수록 결함주입 시험/자원사용 시험의 비중을 높인다.
3. 모든 인터페이스는 최소한 요구사항기반 시험 + 인터페이스 시험을 받아야 한다(생략 불가).
